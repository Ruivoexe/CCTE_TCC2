Vulnerabilidades demonstradas

O mecanismo de download utiliza o parâmetro ?file= para informar à aplicação qual arquivo deve ser solicitado.

No comportamento vulnerável, o valor informado é utilizado diretamente para localizar o recurso, permitindo estudar vulnerabilidades de Path Traversal e File Disclosure.

File Disclosure

Ocorre quando a aplicação permite acessar diretamente um arquivo que existe no ambiente, mas que não deveria estar disponível por meio da interface normal.

No CCTE, determinados arquivos permanecem propositalmente ocultos da listagem de downloads para permitir esse tipo de exercício.

Path Traversal

Ocorre quando elementos do caminho, como ../, são utilizados para navegar para fora do diretório inicialmente esperado.

Isso pode permitir a tentativa de acesso a arquivos localizados em outras partes da estrutura do projeto.

Comportamento educacional

No Modo Educacional, o caminho solicitado pode alcançar diretamente a implementação vulnerável, permitindo observar o comportamento do acesso a arquivos.

Tentativas de Path Traversal ou acesso a arquivos considerados sensíveis continuam sendo monitoradas, classificadas e registradas.

Na Defesa Ativa, o mecanismo de monitoramento pode bloquear requisições classificadas como Path Traversal ou negar o acesso a arquivos classificados como File Disclosure.

Dessa forma, o mesmo teste pode ser repetido nos dois modos para comparar exploração, detecção e resposta defensiva.

DOWNLOADS — VULNERABILIDADES DISPONÍVEIS

File Disclosure

File Disclosure ocorre quando um arquivo que não faz parte dos recursos normalmente apresentados ao usuário pode ser solicitado diretamente pela aplicação.

Nesta página, apenas alguns arquivos são apresentados como downloads legítimos. Entretanto, outros recursos podem existir dentro do diretório utilizado pelo sistema.

Exemplo didático: 

/download?file=files/users.txt

O arquivo users.txt não aparece na lista normal de downloads.

A tentativa de acessá-lo diretamente permite comparar um recurso autorizado pela interface com um arquivo existente, porém oculto da navegação normal.

Path Traversal

Path Traversal ocorre quando o caminho fornecido pelo usuário contém referências destinadas a sair do diretório esperado.

Um padrão típico utilizado durante a experimentação é: 

../

Considerando que os downloads legítimos utilizam o diretório files/, uma tentativa pode ser: 

/download?file=files/../app.py

Nesse exemplo, ../ representa uma tentativa de sair do diretório files/ e alcançar um recurso localizado na raiz do projeto.

O resultado depende da estrutura dos diretórios e do diretório a partir do qual o servidor Flask foi iniciado.

Teste manual

  1. Faça inicialmente o download de um dos arquivos legítimos apresentados na página.
  2. Observe o parâmetro ?file= presente na URL.
  3. Observe que todos os arquivos legítimos apresentados utilizam caminhos iniciados por files/.
  4. Compare um arquivo legítimo com uma solicitação direta ao recurso files/users.txt.
  5. Experimente posteriormente um caminho contendo ../ e observe a resposta da aplicação.
  6. Consulte o Security Log para verificar como a tentativa foi classificada.
  7. Consulte também o Audit Log para verificar os eventos operacionais associados à solicitação.

Comparação dos modos

No Modo Educacional, a solicitação pode alcançar a implementação vulnerável mesmo quando o comportamento é identificado pelo monitoramento.

Na Defesa Ativa, tentativas reconhecidas como Path Traversal podem ser bloqueadas e solicitações classificadas como File Disclosure podem ser negadas.

As técnicas apresentadas devem ser utilizadas exclusivamente no ambiente local e educacional disponibilizado pelo CCTE.
